¿Por qué usar Patrones?

Abstracción Comprobada

Los patrones de diseño no son librerías. Son soluciones conceptuales probadas a problemas recurrentes en el diseño de software orientado a objetos.

Vocabulario Común

Proporcionan un lenguaje estandarizado. Decir "usemos un Adapter" comunica instantáneamente una arquitectura completa al equipo sin necesidad de diagramar cada clase.

1. Adapter Pattern

Clasificación: Patrón Estructural.

Actúa como un envoltorio (wrapper). Permite que objetos con interfaces incompatibles colaboren entre sí.

Se utiliza comúnmente cuando necesitas integrar clases heredadas de terceros, APIs antiguas o bibliotecas externas sin modificar su código fuente original.

// La interfaz esperada por el sistema interface Target { request(): string; } // La clase externa incompatible class Adaptee { specificRequest(): string { return ".eetpadA led acifícepse atseupseR"; } } // El Puente class Adapter implements Target { constructor(private adaptee: Adaptee) {} request(): string { return this.adaptee.specificRequest().reverse(); } }

El Adapter (Arena) rellena el vacío arquitectónico traduciendo las llamadas dinámicamente.

2. Builder Pattern

Clasificación: Patrón Creacional.

Separa la construcción de un objeto complejo de su representación. Evita el "Telescoping Constructor Anti-pattern" (constructores inmensos con múltiples parámetros nulos).

Delega la instanciación a un objeto Builder dedicado, y opcionalmente a un Director que conoce el orden exacto de los pasos.

// Evitamos esto: new House(true, false, 4, null, true, "red"); // Usando el Builder Pattern: const house = new HouseBuilder() .buildWalls(4) .buildDoors(2) .buildRoof("Gable") .hasGarage(true) .getResult();

Visualización: Builder

El algoritmo ensambla un objeto complejo por partes. En este caso, el director ordena: Base → Pilares → Puente superior.

El sistema auto-construye la entidad sistemáticamente. Esta abstracción garantiza que la complejidad arquitectónica final no contamine la inicialización.

3. Iterator Pattern

Clasificación: Patrón de Comportamiento.

Proporciona una forma de acceder a los elementos de un objeto agregado secuencialmente, sin exponer su representación subyacente.

El iterador encapsula toda la lógica de recorrido, manteniendo el código del cliente limpio e independiente de la estructura real (lista, árbol, grafo).

interface Iterator<T> { current(): T; next(): T; key(): number; valid(): boolean; } // El cliente no sabe si 'collection' es Arbol o Array const iterator = collection.createIterator(); while (iterator.valid()) { console.log(iterator.current()); iterator.next(); }

Visualización: Iterator

El cursor (Dorado) actúa como nuestro iterador. Se desplaza a través de una compleja matriz de datos dispuesta en espiral.

El cursor encapsula el estado de navegación de forma autónoma. El cliente desconoce la existencia de una matriz bidimensional, solo pide el elemento "siguiente".

Ingeniería de Software Estructurada

Adapter, Builder e Iterator representan tres pilares fundamentales: integrar, crear y recorrer de forma predecible y segura.
